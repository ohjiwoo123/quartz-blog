### Cookie 란 ?
서버가 사용자의 웹 브라우저에 전송하는 작은 데이터 조각이다. 브라우저는 이 데이터 조각들을 저장해놓았다가 동일한 서버에 재요청시 저장된 데이터를 함께 전송한다. 쿠키는 두 요청이 동일한 브라우저에서 요청하였는지 판단할 때 주로 사용한다. 
이것을 이용하면, 사용자의 로그인 상태를 유지할 수 있다.

1. 세션 관리 
2. 개인화
3. 트래킹 

### Signed Cookie (서명된 쿠키)란 ?
- 서버에서 **비밀 키(secret key)**를 사용해 쿠키 값에 대한 디지털 서명을 붙여 발급합니다.

클라이언트는 쿠키 값을 변경할 수 있지만, 서명이 일치하지 않으면 서버에서 위조된 쿠키로 판단해 거부합니다.

SHA-256 같은 것으로 암호화함.  

### 쿠키와 캐시의 개념차이   
|항목|쿠키 (Cookie)|캐시 (Cache)|
|:---:|:---:|:---:|
|목적|클라이언트 상태 저장하여 세션 유지|리소스를 재사용하여 성능 최적화|
|저장 위치|브라우저 로컬 저장소 (Cookies)|브라우저 캐시, 디스크, 메모리, CDN 등|
|저장 내용|사용자 정보, 세션 ID, 로그인 상태 등 작은 데이터|html, js, css, 이미지, 동영상 조각 등 대용량 리소스|
|용량 제한|보통 도메인당 4KB|수십 MB ~ 수백 MB|
|만료 방식|Expires or Max-Age|Cache-Control, Etag, Last-Modified|
|전송 방식|매 요청마다 HTTP Cookie 헤더로 서버에 자동 전송|동일 리소스 요청 시 서버 요청 없이 로컬에서 사용|
|보안성|민감 정보 가능 -> HttpOnly, Secure 필요|주로 정적 리소스 (민감정보는 보통 저장하지 않음)|
|사용 예시|로그인 유지, 사용자 설정, 광고 트래킹|이미지, CSS, JS, HLS, TS 세그먼트 등 정적 리소스|
