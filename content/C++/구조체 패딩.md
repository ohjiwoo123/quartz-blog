```
struct Aligned
{
 	char c1;	// 1 bytes
    int i4a;	// 4 bytes
    int i4b;	// 4 bytes
    double d8;	// 8 bytes
};

total : 19 bytes ? No
total : 24 bytes ? Yes

int main()
{
	std::cout << sizeof(Aligned);
};
```

|1 - 4|4 - 8| 8 - 12| 12 - 16|16 - 24|
|---|:---|:---:|---:|---:|
|c1(1bytes) padding (3bytes) | i4a (4 bytes)|i4b (4bytes)|padding| d8 (8bytes)|

구조체를 위처럼 만드는 경우, 
실제론 이렇게 패딩이 일어나게 된다.

사이즈가 가장 큰 바이트를 기준으로 정렬 해줘야 한다.  

1 race condition
2 false sharing 
3 AUX, SSE -> SIMD 인스트럭션
CPU는 데이터 액세스 타임을 줄이기 위해서 캐시를 사용하는데, 캐시의 가장 작은 기본 단위인
캐시라인(Cache Line) 64bytes 을 사용한다.   

C+11 부터 
`alignas specfier` 
병렬프로그래밍을 하는데 있어서 캐싱문제가 일어나지 않게 된다.

ex 
```
struct alignas(32) Aligned
{
    double d8;	// 8 bytes
    int i4a;	// 4 bytes
    int i4b;	// 4 bytes
 	char c1;	// 1 bytes
};

사이즈가 가장 큰 바이트를 기준으로 정렬 됨.  
total : 17 bytes ? No
total : 24 bytes ? Yes

int main()
{
	std::cout << sizeof(Aligned);
};
```


구조체 패딩을 아래와 같이 제거하는 방법도 있다.
```
#pragma pack(push,1)
typedef struct test{
    char a;
    int b;
}test;
#pragma pack(pop)
```

최종적인 결론은 아래와 같다

🟢 패딩을 유지하는 게 더 나은 경우:
1 성능이 중요한 일반적인 프로그램

2 CPU 캐시라인 정렬이 중요할 때 (예: 게임, 수치 연산 등)

3 구조체를 자주 생성/복사/연산하는 경우

🔴 패딩을 없애는 게 더 나은 경우:
1 구조체를 디스크에 저장하거나 네트워크로 전송할 때 (e.g., 바이너리 프로토콜)

2 메모리를 아주 많이 절약해야 할 때 (예: 수백만 개 구조체)

최종적으로는 패딩을 유지하고 정렬을 잘하는 방법으로 사용하는 것이 좋은 프로그래밍 습관이라고 할 수 있겠다.
