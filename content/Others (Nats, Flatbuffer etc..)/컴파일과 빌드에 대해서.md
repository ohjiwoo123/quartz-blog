### 컴파일순서 

소스코드가 어떻게 실행파일이 되는가?

컴파일이란? 인간이 이해할 수 있는 언어(C,C++등)를 CPU가 이해할 수 있는 (기계어)로 변환하는 작업이다.

컴파일 과정


1. 헤더파일(.h), 소스코드(.c) --> 전처리 (PRE-PROCESSING)
2. *.i (전처리된 소스 코드 파일) --> 컴파일 (Compile)
3. *.s (어셈블리어 파일) --> 어쎔블리 (Assembly)
4. *.o (오브젝트 파일), *.a *.so (라이브러리파일) --> 링킹 --> 실행파일 

전처리(*.i) -> 컴파일(*.s) -> 어셈블리(*.o) -> 링킹 -> *.exe


### 전처리 (Pre-Processing)
1. 주석 제거
2. 헤더파일 삽입 (헤더파일에 있는 모든 내용을 복사해서 소스코드에 삽입)
3. 매크로 치환 및 적용 (#define 처리)


### 컴파일 (Compliation)
1. 전처리된 소스코드 파일(*.i)을 어셈블리어(*.s)로 변환하는 과정
2. 이 과정에서 언어의 문법 검사가 이루어지고, Static (Data, Bss)영역들의 메모리 할당을 수행한다.

### 컴파일러 구조
컴파일러는 세 단계로 구성되어있다.
프론트엔드-미들엔드-백엔드

GNU에서 만든 C 컴파일러인 gcc는 프론트/미들/백 잘 분리되어 있지 않고, 의존성이 존재한다.
오픈소스 C 컴파일러인 Clang(프롱트엔드) LLVM(미들엔드,백엔드) 단계가 잘 분리되어 있다.

### 어셈블리(Assembly) 과정
어셈블러를 통해 어셈블리어 파일 *.s를 오브젝트 파일 *.o로 변환하는 과정이다.

### 빌드 관련 파일 및 용어 
1. CMakeLists.txt 
- cmake에게 프로젝트를 어떻게 빌드할 것인지 알려주는 파일
```
1) 프로젝트 이름
2) C++ 버전
3) 어떤 .cpp를 컴파일할지
4) 어떤 라이브러리를 사용할지
5) include 경로
6) 컴파일 옵션
7) 링크할 라이브러리
8) 실행 파일 / 라이브러리 생성 방법
9) 하위 디렉토리 구조
```

2. CMakePresets.json
- CMake를 실행할 때 사용할 설정들을 미리 정의해놓는 파일
(debug, prod 분리, 빌드도구 설정 등

3. CMake
- CMakeLists.txt, CMakePresets.json를 이용해서 빌드 시스템 생성

4. Makefile / build.ninja
- CMake가 생성한 실제 빌드 규칙

5. make / ninja
- 규칙을 보고 실제 컴파일/링크 수행 

Make = 빌드 도구
Makefile = Make가 읽는 빌드 규칙 파일

Ninja = 빌드 도구
build.ninja = Ninja가 읽는 빌드 규칙 파일 

CMake는 빌드 파일을 만들어주는 역할이고, Make/Ninja는 그 빌드 파일을 읽어서 실제 빌드를 수행하는 역할이다.

ninja는 빌드를 빠르게 수행하는 것에 초점을 맞춘 빌드 도구인데,
main.cpp
A.cpp
B.cpp
C.cpp 가 있으면,

만약 A.cpp만 수정했다고 하면 A.cpp -> A.o만 다시 컴파일 한다.
